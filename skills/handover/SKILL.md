# handover（跨角色交接与接收确认）

> 交接单责任角色由规范明确（§8.4）：**上游角色起草、下游角色确认接收，项目总管负责交接流程跟踪、接收确认超时升级与交接争议仲裁**；交接物中的门禁结论由其出具角色签署，门禁责任不随交接转移。
> 硬约束：交接物不得含"请下游直接改上游产物"的越界指令（§8.5）。

## 1. 触发条件

1. 上游产出物需移交下游：开发 → 测试、测试 → 发布、开发 → 文档维护员、文档维护员 → 发布。
2. 任务卡 §15 要求的交付物或文档初稿完成，需要按交接物移交。
3. 下游收到不完整交接物，需要退回并重交。
4. 发版前跨角色的批量交接。
5. 缺陷修复后的回归物移交。

不适用：任务卡生成（`task-card`）；门禁结论出具（`release-gate-check`、`test-report`、`document-checklist`）；用户业务验收（§3.5）。

## 2. 输入

| 输入 | 说明 | 缺失时处理 |
|---|---|---|
| 上游任务卡 | 任务 ID、Owner、状态、范围 | 阻断 |
| 交接物清单 | 名称、类型、版本、位置 | 阻断（§8.4） |
| 上游自检清单 | 开发 → 测试必附 | 阻断 |
| 测试结论 | 测试 → 发布必附 | 阻断 |
| 已知问题 | 未关闭缺陷、遗留告警、临时方案 | 阻断 |
| 待决事项 | 需下游/总管/用户决策的条目 | 阻断 |
| 验收点 | 下游按什么判定接收 | 阻断 |
| 模板 | `docs/team-management/templates/handover.md` | 阻断 |

## 3. 前置检查

> **D0 规范与模板定位（所有 skill 通用，先于其余检查）**：本 skill 引用的规范与模板均为仓库相对路径 `docs/team-management/...`。定位顺序：① 环境变量 `TEAM_MGMT_ROOT`；② 以本 SKILL.md 所在目录为基准逐级向上查找 `docs/team-management/` 目录；③ 当前工作目录下的 `docs/team-management/`。三者均未命中 → 按 §6 阻断，并提示设置 `TEAM_MGMT_ROOT` 或以本仓库为工作目录。定位到的根目录记为 `MGMT_ROOT`，下文出现的 `docs/team-management/...` 一律相对 `MGMT_ROOT` 解析。

| 编号 | 检查项 | 判定标准 |
|---|---|---|
| P1 | 上游工作已达可交接状态 | 开发类已附自检清单；测试类已附测试结论（§8.6） |
| P2 | 交接物清单完整 | 每项有名称、类型、版本、位置 |
| P3 | 版本与实际一致 | 版本号可追溯，防止旧版交接 |
| P4 | 已知问题已列 | 未关闭缺陷、遗留告警、临时方案逐条列出 |
| P5 | 待决事项明确 | 标注决策人与期限 |
| P6 | 验收点可判定 | 下游能按条目判断"收/不收" |
| P7 | 下游接收人明确 | 已指定具体角色与人员 |
| P8 | 无跨职责越界 | 交接物不含让下游直接改上游产物的指令（§8.5） |

| P10 | 模板可用 | 模板文件存在 |

## 4. 执行步骤

1. **取上游材料**：载入任务卡与其全部产出物、已附的自检清单或测试结论。
2. **校验 P1**：开发 → 测试无自测清单、测试 → 发布无测试结论 → 不得发起交接（§8.6）。
3. **校验版本**：逐项核对交接物版本与实际内容；版本不符或缺失 → 不得交接。
4. **起草交接单**：填交接物清单、已知问题、待决事项、验收点、上下文包链接。
5. **附上游结论**：把自检清单或测试结论作为交接物之一登记（注明出具方，不改其结论）。
6. **移交下游**：发送交接单给下游接收人，明确确认时限，并提示门禁类结论由其出具方签署。
7. **下游核对**：下游按验收点逐条核对——交接物是否齐、版本是否对、能否直接开工、是否越界。
8. **下游填结论**：接收 → 填签署与时间；退回 → 列出缺项。
9. **退回重交**：上游按缺项补充，重新发起并**递增版本号**；每次退回与重交写入交接单 §7。
10. **更新状态**：接收确认后更新任务卡状态（§5.2），交接单归档到与任务卡关联的位置。
11. **提示门禁归属**：若交接物含质量门禁结论或文档门禁结论，明确门禁责任仍属其出具角色，下游不得代签或改写。

## 5. 输出

| 输出 | 路径 / 位置 | 说明 |
|---|---|---|
| 交接单 | `docs/team-management/templates/handover.md`，实际文件 `handover-<TASK-ID>-<NN>.md` | 含交接物、版本、已知问题、待决事项、验收点 |
| 接收确认记录 | 交接单 §6 | 接收 / 退回结论、下游签署与时间 |
| 退回与重交记录 | 交接单 §7 | 次数、原因、缺失项、重交版本 |
| 任务卡状态更新 | 任务卡 §1「状态」 | 按 §5.2 状态流转，并关联交接单编号 |
| 归档位置 | 交接单 §1 / 任务卡 §15 | 可追溯的留痕位置 |

下游消费方：下游执行角色、项目总管（跟踪接收确认与超时升级）。

## 6. 拒绝/阻断条件

| 编号 | 条件 | 处置 |
|---|---|---|
| H1 | 上游未附自检清单（开发 → 测试） | **不得交接**（§8.6、§10.4） |
| H2 | 上游未附测试结论（测试 → 发布） | **不得交接**（§8.6） |
| H3 | 交接物无版本或版本与实际不符 | 不得交接，先修正版本 |
| H4 | 交接单缺已知问题或待决事项 | 补齐后重交 |
| H5 | 下游把"直接修改上游产物"作为接收条件 | 拒绝该条件，退回并按 §8.5 处置 |
| H6 | 交接实质是范围变更 | 改走 `change-impact`，不按交接处理 |
| H7 | 门禁结论由非出具方代签或改写 | 拒绝，门禁责任不随交接转移（§2.3、§8.5） |
| H8 | 交接内容超出上游任务卡范围 | 拒绝该部分，先补任务卡或走变更 |
| H9 | 无明确下游接收人或验收点不可判定 | 不得交接 |
| H10 | 模板文件缺失 | 阻断，先补模板 |

## 7. 升级规则

1. 下游接收确认 **2 小时**未回 → 升级项目总管（§7.4.1）。
2. 同一交接被退回 **≥3 次** → 升级复盘，检查需求、契约或方案问题（§7.4.3）。
3. 双方对验收点理解不一致 → 项目总管仲裁（§7.4.2）。
4. 交接物含门禁结论争议 → 由项目总管组织评审，**不得无依据强行放行**（§7.4.2、§7.5）。
5. 交接阻塞导致下游任务超期 → 升级项目总管重排优先级与排期（§7.2）。
6. 上游与下游均认为对方越界 → 项目总管仲裁并明确职责边界。

## 9. 示例

**输入**

> 上游：后端开发工程师，任务 TASK-20261021-01（开发中 → 待测试）。产出物：导出接口代码（v1.2）、接口契约 IC-20261012-01 v2（已会签）、开发自测清单（3 项通过）。已知问题：3 万行以上未压测。待决事项：退款行口径待用户确认。

**输出（摘要）**

- 交接单 `handover-TASK-20261021-01-01.md`，交接物 3 项均带版本；自检清单作为交接物之一登记。
- 已知问题：3 万行以上未压测（一般，影响 AC-2 验证范围）；待决事项：退款行口径 → 决策人：项目总管（转用户确认）→ 期限。
- 验收点：接口按 IC v2 可调用；自测 3 项复现通过；已知问题已列明。
- 下游（质量检测员）核对后接收 → 签署，任务卡状态改为"待测试"。
- 若质量检测员以"直接改掉退款行口径的代码再测"作为接收条件 → 触发 H5，拒绝该条件，转待决事项走用户确认；不得由质量检测员改后端产物（§8.5）。
